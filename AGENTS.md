# MargMap – Agent Instructions

## What This Is

A vanilla JS + [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/) pizza-rating map app, built with [Astro](https://astro.build/) and deployed as a single Cloudflare Worker via the `@astrojs/cloudflare` adapter. No UI framework (no React/Vue) — Astro components (`.astro`) are used purely for templating, and all interactivity is plain JS in `src/scripts/main.js`. Data lives in Google Sheets, flows through a CSV→JSON pipeline.

The homepage is a single prerendered static page, but is structured as an Astro template (layout + components) so additional routes — e.g. a page per restaurant — can be added later under `src/pages/`. The Google Places photo proxy lives alongside it as on-demand API routes (`src/pages/api/`), so the whole app builds and deploys as one Astro project — there's no separate hand-written `worker.js` anymore.

## Project Structure

```
src/
  pages/
    index.astro              # Route: / (prerendered static page)
    api/
      place-photo/[placeId].js         # On-demand: photo metadata lookup
      place-photo-media/[placeId].js   # On-demand: photo media proxy (cached)
  layouts/Layout.astro        # <html> shell: head/meta, CSS import, main.js script tag
  components/                 # Header, MobileFilters, Sidebar, MobileDetailView
  lib/photos.js                # Shared helpers for the two photo API routes
  scripts/main.js             # All client-side interactivity (map, filters, detail views)
  styles/main.css             # Tailwind + MapLibre GL + custom styles
  data/                       # ratings.csv (committed), google-places.json (committed)
public/
  data/ratings.json           # Generated by `pnpm prepare-data`, gitignored
```

## Architecture Overview

```
Google Sheets (source of truth)
    └─ pnpm update-data ──→ src/data/ratings.csv  (committed)
                              ├─ src/data/google-places.json
                              └─ pnpm prepare-data ──→ public/data/ratings.json
                                                            └─ Astro build ──→ dist/client/data/ratings.json
```

- `astro.config.mjs` uses the `@astrojs/cloudflare` adapter, output split into `dist/client/` (static assets, served via the `ASSETS` binding) and `dist/server/entry.mjs` (the Worker script). The adapter writes its own `dist/server/wrangler.json` pointing at these; `wrangler dev`/`wrangler deploy` auto-detect and use it ("Using redirected Wrangler configuration") instead of the root `wrangler.jsonc`. Deliberately **don't** add `main`/`assets` to the root `wrangler.jsonc` — pointing them at `dist/` paths that don't exist yet breaks a clean `astro build` (the Cloudflare Vite plugin eagerly validates `main` exists at config-load time).
- The homepage (`src/pages/index.astro`) is prerendered to static HTML at build time. The two photo API routes each set `export const prerender = false;` so they run on-demand as Worker requests. Env bindings (`GOOGLE_MAPS_API_KEY`) come from `import { env } from 'cloudflare:workers'`, `waitUntil` from `context.locals.cfContext`, and the Cache API from the global `caches` object — `context.locals.runtime.*` was removed in this Astro version and throws if used.
- Tailwind CSS v4 is wired in via the `@tailwindcss/vite` plugin (registered in `astro.config.mjs`), not `@tailwindcss/postcss` — Astro/Vite's built-in CSS `@import` resolution conflicts with the PostCSS plugin approach.
- **`src/data/ratings.csv` is checked in** – this intentional design means builds don't require a network call to Google Sheets. `public/data/ratings.json` is generated and gitignored.

### Known pinned versions (read before touching deps)

Three dependency pins exist purely to route around upstream bugs current as of this writing. Don't "clean these up" without re-testing:

- `maplibre-gl` is pinned to the exact version `5.24.0` (no caret). MapLibre GL JS `6.x` ships as multi-file ESM (`maplibre-gl.mjs` + a dynamically-imported `maplibre-gl-shared.mjs` + `maplibre-gl-worker.mjs`); Astro's Rolldown bundler doesn't emit the worker's sibling chunk, so the tile worker fails on its first import — the map mounts, the style and `tiles.json` load, but **no vector tiles are ever requested**, `map.loaded()` never becomes true, and the `load` event never fires. `5.x` ships a single classic `maplibre-gl.js` with the worker inlined as a blob, which bundles cleanly. Revisit once MapLibre fixes ESM worker bundling (or the adapter's bundler handles it).
- `wrangler` is pinned to the exact version `4.116.0` (no caret). `wrangler` ≥4.118 bundles an alpha `miniflare` 5.x; `@cloudflare/vite-plugin` (a transitive dep of the adapter) also keeps raising its minimum required `wrangler` version. `pnpm-workspace.yaml` additionally overrides `@cloudflare/vite-plugin` to `1.49.0`, the last release whose floor (`wrangler ^4.116.0`) still matches.
- `astro.config.mjs` sets `prerenderEnvironment: 'node'` on the adapter. Without it, `astro build` crashes prerendering *any* static page (even one with zero application code) with `TypeError: This ReadableStream is disturbed...` from inside `@astrojs/cloudflare`'s sandboxed-workerd prerender server — see [withastro/astro#17600](https://github.com/withastro/astro/issues/17600). This is unrelated to the wrangler pin above (reproduces on stable and alpha `miniflare` alike, on Node 22 and 25, and on Astro 6 and 7). Once upstream fixes it, this option can be removed and prerendering will use `workerd` again — the default.

## Key Commands

| Command | Effect |
|---|---|
| `pnpm dev` | Astro dev server at `http://127.0.0.1:8787` — serves the frontend and the `/api/*` routes together (via the adapter's platform proxy) |
| `pnpm build` | Runs `prepare-data`, Astro build, then updates the README table |
| `pnpm check` | Non-mutating CI validation: regenerate data, build |
| `pnpm preview` | Serve the production Worker locally via `wrangler dev` at `http://localhost:8788` — closer to real Cloudflare behavior than `pnpm dev` |
| `pnpm fetch-csv` | Pull fresh CSV from Google Sheets only |
| `pnpm fetch-data` | Pull fresh CSV from Google Sheets + convert to JSON |
| `pnpm prepare-data` | Convert existing `ratings.csv` → `public/data/ratings.json` only |
| `pnpm enrich-google-places` | Add missing Google place IDs for photo lookups |
| `pnpm update-data` | Fetch CSV, enrich place IDs, regenerate JSON, and sync README |
| `pnpm update-readme` | Sync README restaurant table from CSV |
| `pnpm ship` | Full build + `wrangler deploy` to Cloudflare |
| `pnpm clean` | Remove `src/data/ratings.csv`, `public/data/ratings.json`, and `dist/` |

`pnpm dev` runs `astro dev` as a background daemon (this Astro version's default) — use `astro dev status`, `astro dev logs`, or `astro dev stop` to manage it directly if needed.

## Data Schema

Each restaurant record (fields in `ratings.json`):

- **`mScore`** – overall rating (1–10 float); use this for all rating comparisons
- Dimension scores (0–10 int): `Crust`, `Dough`, `Sauce`, `Cheese`, `Basil`, `Sliced`, `Sloppiness`, `Saltiness`, `Oiliness`
- `Name`, `Location`, `Country`, `Date` (DD/MM/YYYY), `Price` (£-prefixed string), `Lat`, `Lon`

## UI Patterns

- **Dual desktop/mobile inputs**: every filter control has two DOM elements, e.g. `#search-input` / `#search-input-mobile`. They are kept in sync via `syncFilters()` in `src/scripts/main.js`. Always update both IDs when adding new filter controls.
- **Rating colour bands**: ≥8 → red, ≥7 → orange, ≥6 → yellow, else gray. Applied in both Tailwind classes (`getRatingColor`) and hex colours for the MapLibre markers (`updateMapMarkers`).
- Map uses CARTO's Voyager **vector** basemap (`voyager-gl-style/style.json`) rendered by MapLibre GL JS. Markers are plain `<div class="marker-badge">` elements wrapped in `maplibregl.Marker`; popups are `maplibregl.Popup` with `.setHTML()`. Coordinates are passed to MapLibre as `[lon, lat]` (opposite of Leaflet's `[lat, lon]`).
- `main.js` is loaded via a `<script>` tag in `src/layouts/Layout.astro` (`import '../scripts/main.js'`), bundled by Astro/Vite like any other module.

## Scripts

- `scripts/csv-to-json.js` – standalone Node ESM script; also exported as `csvToJson` for programmatic use. Takes arbitrary input/output paths and creates the output directory if needed.
- `scripts/enrich-google-places.js` – stores Google place IDs in `src/data/google-places.json`; it only requires `GOOGLE_MAPS_API_KEY` when missing restaurants need matching.
- `scripts/update-readme-table.js` – rewrites the `## Restaurant Ratings` section in `README.md` between the two heading markers. Run after any data change.

## Deployment

Deployed via **Cloudflare Workers** (`wrangler.jsonc`), not Cloudflare Pages. `wrangler.jsonc` holds `name`, `account_id`, `compatibility_date`, and `routes`; the `main`/`assets` entries are supplied by the adapter's generated `dist/server/wrangler.json`, which `wrangler` auto-redirects to at build/deploy time (see above). Custom domains `margmap.com` and `www.margmap.com` are configured directly in `wrangler.jsonc`. Deploy with `pnpm ship`.

`GOOGLE_MAPS_API_KEY` is read locally from a `.dev.vars` file (standard Wrangler convention; gitignored) — both `pnpm dev` and `pnpm preview` pick it up. In production it's a Worker secret set via `wrangler secret put GOOGLE_MAPS_API_KEY`.

## Adding a New Restaurant

1. Add the row to the Google Sheets document.
2. `pnpm update-data` – updates CSV, Google place IDs, JSON, and README.
3. `git add src/data/ README.md && git commit -m "Add <restaurant name>"`
4. `pnpm ship` to deploy.

## Adding a New Page

Astro uses file-based routing: add a `.astro` file under `src/pages/` and it becomes a route (e.g. `src/pages/restaurants/[slug].astro` for a page-per-restaurant using `getStaticPaths()` over `public/data/ratings.json`). Reuse `src/layouts/Layout.astro` and the existing `src/components/` for a consistent shell. New pages are prerendered by default; add `export const prerender = false;` only if a route needs to run on-demand (like the photo API routes).
